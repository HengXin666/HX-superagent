# HX-superagent 面板重构计划 v7 (开发总监)

日期: 2026-11-15 02:30 CST · 工作目录: /home/hx/Loli/code/HXLoLis/components/HX-superagent · 分支 feat/panel-v2 · 上一版: docs/panel-v6-plan.md

## 一、意图拆解

你这次说的其实是四件事, 外加一件没明说但最要紧的事:

1. **预设要"我的", 而且要能叠.** 现在 Agent 预设只能单选、只能从 DSH 注册表里挑. 你要的是: 自己建预设、给一个角色勾多个、能排序、知道叠完后到底生效了什么.
2. **交互要"实时", 而且要顺手.** 操作后要立刻看到结果; 别人或调度改了状态, 页面也要马上变. 流程顺序要贴合"发现问题 → 就地处理 → 看到影响"的习惯.
3. **UI 要有现代感, 不廉价.** 统一设计语言、明暗主题、四态完整、键盘可用, 不是零碎补样式.
4. **要能"看见"系统.** 配置时有一张架构/调用关系图告诉你"我正在改第几步的哪一段、会影响谁"; 运行时有一个监控台告诉你"调度在流转什么、我们在做什么、哪里卡住".
5. **(隐含) 这一次要真的落到眼前.** 仓库里已有 v3 到 v6 四版计划, 你还在提同样的需求, 说明问题不在方向, 在落地. 所以本版每条线都要求"先交一个你能看到的切片", 验收里都有实机项, 最后一条线专管本机一次跑通.

## 二、现状 (经 hxoa 只读核查)

- 预设: Agent 预设单选且只取 DSH 注册表(注册表运行时不能新增); 能力包、Prompt 预设可多选但是两个独立概念. 体感就是"只能选它里面的".
- 实时: 已有 live feed(含 health/stage/activity 等主题)和前端订阅客户端, 但前端各视图仍自带轮询, 部分事件缺发出点或丢标识, 乐观更新没有统一落点.
- UI: src/client/ui 新组件库与旧控件层并存, 样式大量写死, 暗色未验证.
- 可视化: 已有五步管线图和 Console 泳道/事件流, 但节点只到"步", 图与配置弱联动, 监控台偏日志.
- 工作树: 大量未提交改动; 仓库根 .hxoa 目录里有登录凭据和打包副本, 绝不能进提交.

## 三、相对 v6 的调整

- 方向延续 v6, 不重新设计.
- **预设线提为第一优先**, 且独立开工, 因为它是你最直接的痛点, 也最容易让你"看到变化".
- 每条线先交可见切片(截图或可点的页面), 方向不对早停.
- 交付线明确把 .hxoa 凭据目录排除在提交之外.

## 四、顺序

线1(预设)、线2(实时底座) 同时开工 → 线3(设计语言) 在线2 的共享层可用后迁页面 → 线4(地图 + 监控台) 依赖 1/2/3 → 线5 收口.
